# EcoAI API Contract

This document describes the backend routes currently implemented in `backend/server.js`.

## Base URL

Local development: `http://localhost:5000`

## Endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/` | Confirms that the backend is responding. |
| GET | `/api/health` | Returns a health-check response. |
| GET | `/api/usage` | Retrieves usage records from Firestore, newest first. |
| POST | `/api/usage` | Validates and saves a usage record to Firestore. |

## GET /

Example response:

```text
Green AI Backend is running!
```

## GET /api/health

Example response:

```json
{
  "status": "OK",
  "message": "Backend is healthy"
}
```

## GET /api/usage

Returns records from the Firestore `usageRecords` collection, ordered by `createdAt` descending.

Example response shape:

```json
{
  "records": [
    {
      "id": "FIRESTORE_DOCUMENT_ID",
      "electricity": 2.5,
      "water": 10,
      "ewaste": 0.2,
      "aiUsage": 15,
      "createdAt": "2026-10-15T10:00:00.000Z"
    }
  ]
}
```

The ID, timestamp, and values are illustrative, not actual stored data.

If retrieval fails, the server returns HTTP 500:

```json
{
  "message": "Failed to fetch usage records"
}
```

## POST /api/usage

All four fields are required. Each must be a finite, non-negative JSON number.

Example request:

```json
{
  "electricity": 2.5,
  "water": 10,
  "ewaste": 0.2,
  "aiUsage": 15
}
```

| Field | Meaning | Expected unit |
| --- | --- | --- |
| `electricity` | Electricity usage | kWh |
| `water` | Water usage | Litres |
| `ewaste` | Electronic waste | kg |
| `aiUsage` | AI usage count | Prompts/requests |

Confirm the units used by the frontend before treating them as definitive. The API validates numeric values but does not convert units.

### Successful response

HTTP 201 Created.

```json
{
  "message": "Usage saved to Firestore successfully",
  "id": "FIRESTORE_DOCUMENT_ID",
  "record": {
    "electricity": 2.5,
    "water": 10,
    "ewaste": 0.2,
    "aiUsage": 15,
    "createdAt": "2026-10-15T10:00:00.000Z"
  }
}
```

The document ID and timestamp are generated by the backend.

### Validation error

HTTP 400 Bad Request.

```json
{
  "error": "electricity must be a non-negative number"
}
```

The field named in the error depends on the invalid input.

### Storage error

HTTP 500 Internal Server Error.

```json
{
  "error": "Could not save usage data"
}
```

## Data storage and credentials

Usage records are stored in the Firebase Cloud Firestore collection `usageRecords`.

The backend currently loads Firebase Admin credentials from `backend/serviceAccountKey.json`. Keep this credential file private and exclude it from version control.

## Scope

This document lists routes verified in the current backend source. Do not assume that dashboard, report, suggestions, feedback, or prompt-optimization API endpoints exist unless they are implemented and verified separately.
